# 文档与运维实施文档

## 当前状态

项目已有 README、设计文档、文件结构说明、工程化路线、评测路线、部署脚本和 CI。但这些材料处于不同阶段：有的描述早期架构，有的描述新实现，有的使用旧指标。新成员容易把历史设计误认为当前行为。

## 目标

让非开发人员能理解系统如何工作，让开发人员能准确启动、测试、迁移和恢复，让文档和代码在功能变化后不会长期分叉。

## 文档分层

### 面向使用者

- 产品能做什么、不能做什么
- Steam ID 为什么需要绑定
- 推荐结果为什么可能没有价格或实时信息
- 数据删除、记忆和隐私说明

### 面向开发者

- 当前架构和模块边界
- API 请求/响应及 SSE 事件
- 环境变量参考
- 本地开发、测试、索引构建和评测命令
- 数据库表、Chroma collection 和迁移说明

### 面向运维人员

- Docker 启动、升级、停止和回滚
- 密钥配置和轮换
- 数据备份与恢复
- 健康检查、日志、metrics 和常见故障处理
- 索引更新和失败后的回滚

## 运行手册最低内容

### 启动前

- Python/Docker 版本
- DeepSeek 和 Steam key 是否配置
- Chroma 索引是否存在且 manifest 匹配
- SQLite 和 checkpoint 目录是否可写

### 运行中

- 查看 readiness、请求 ID 和 metrics
- 区分模型错误、Steam 错误、检索空结果和预算降级
- 不直接删除数据库或 Chroma 文件夹

### 升级时

- 备份 SQLite、checkpoint、Chroma 和 `.env` 配置名清单
- 先构建新镜像和新索引
- 执行迁移和确定性测试
- 小范围验证后再切换流量
- 保留上一版本镜像和索引用于回滚

### 恢复时

- 先停止写入或进入维护模式
- 从同一时间点恢复相关数据层
- 校验消息、检查点和语义记忆数量
- 记录恢复结果和未恢复的数据

## 验收标准

- 新人仅按文档可以完成本地启动和测试。
- 运维人员可以在不阅读源码的情况下完成升级、回滚和数据备份。
- 文档中的每个“已完成”都能指向当前代码、测试或评测证据。
