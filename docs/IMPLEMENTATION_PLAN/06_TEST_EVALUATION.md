# 测试、评测与可观测性实施文档

## 当前状态

项目已有单元测试、工具故障注入、Agent 运行时测试、混合检索测试、记忆测试和 CI。`evals/` 中有数据集、baseline、评测 runner、报告和 GitHub Actions 工作流。

现有体系更擅长验证 Agent 逻辑和推荐质量，仍需补充真实 API 安全边界、重启恢复、跨用户隔离和索引切换测试。不同文档中的 RAG 基线来自不同版本，必须统一口径。

## 目标

每次改动都能说明：功能是否仍然正确、数据是否安全、回答质量是否变化、成本和延迟是否变化。

## 测试分层

### 1. 快速确定性测试

每次提交都运行：

- schema 和 API 契约
- 工具策略、预算、重试和熔断
- 记忆去重、冲突、TTL
- RAG BM25、RRF、过滤和降级
- 身份授权和跨用户隔离
- 代码编译检查

### 2. 服务集成测试

使用本地 SQLite、临时 Chroma 和模型/工具 mock，验证：

- 登录到聊天的完整链路
- 同步和流式聊天
- 线程历史、标题和删除
- 归档双写和补偿
- 重启后继续会话
- readiness 和 metrics

### 3. 评测门禁

继续使用固定数据集和 baseline，但每份报告必须记录：

- git SHA
- prompt hash
- 模型和参数
- 数据集 hash
- 索引 manifest hash
- 重复次数
- 成本、token 和延迟

付费 LLM 评测不应只看总通过率，还要审查失败用例、工具链成功率、无证据推荐、重复调用和 P95 长尾。

### 4. 故障注入

至少覆盖：

- DeepSeek 超时、限流、返回异常
- Steam API 超时、429、5xx 和空用户库
- Chroma 不可用、索引缺失、查询返回空
- embedding/reranker 模型加载失败
- SQLite 锁定、磁盘写入失败
- SSE 客户端中途断开

## 指标建议

### 用户体验

- 请求成功率和降级率
- 同步总耗时 P50/P95/P99
- SSE 首 token 时间 TTFT
- 流式取消率

### Agent 运行

- 每次工具轮数和工具调用数
- 重复调用拦截次数
- token 使用和估算成本
- 各工具成功、空结果、超时、限流、熔断次数
- grounding 校验失败和 safe fallback 次数

### 数据和安全

- 归档失败和补偿积压
- Chroma/SQLite 数量差异
- 索引当前版本和过期版本
- 登录失败、授权拒绝和异常删除尝试

指标不得包含密码、API key、完整 token 或完整用户对话。

## 基线治理

- 旧 baseline 标记为历史版本，不能和当前版本混称。
- 新 baseline 只能显式提升，不能由评测脚本自动覆盖。
- 任何指标下降都要说明是数据集变化、模型变化、索引变化还是代码回归。
- RAG 的 test/dev 划分和指标名称保持一致，文档只引用一份当前基线。

## 验收标准

- 安全、持久化和索引相关任务都有自动化回归测试。
- CI 能在没有真实 Steam 用户数据的情况下完成确定性门禁。
- 真实模型评测失败时能定位到具体 case、工具链和版本信息。
- `/metrics` 的数据和评测报告能解释同一类线上问题。
