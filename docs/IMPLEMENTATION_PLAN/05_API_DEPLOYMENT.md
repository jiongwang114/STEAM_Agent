# API、前端与部署实施文档

## 当前状态

服务由 FastAPI 和 Uvicorn 提供，支持同步聊天、SSE 流式聊天、线程历史、Steam 绑定、认证和 `/metrics`。Docker 使用本地 Chroma、SQLite 数据卷和模型缓存。当前应用内的锁、指标和缓存主要是单进程内状态。

## 目标

让开发、测试和线上部署使用一致的启动方式；让接口错误、健康状态、流式断开和数据卷行为都可以被运维人员理解。

## 实施方案

### 1. API 设计

- 用户名、密码、Steam ID、主题和聊天数据使用 JSON body 或授权 Cookie，不用 query 参数传敏感内容。
- 为错误响应定义稳定格式：错误码、用户提示、请求 ID、是否可重试。
- 为 `/chat` 和 `/chat/stream` 固定版本化契约，保持向后兼容。
- 对 thread、message 和 Steam ID 做格式校验，不依赖模型自行纠错。
- 明确流式事件顺序：状态事件、token 事件、done 事件；发生错误时也必须能结束流。

### 2. 健康检查

拆成两类：

- 存活检查：进程和 HTTP 服务是否还在。
- 就绪检查：SQLite、Chroma、embedding 模型和必要的配置是否可用。

当前 `/health` 返回固定成功，不足以发现模型、向量库或配置问题。Docker 的 readiness 检查应使用就绪检查，但不能让健康检查本身触发昂贵的模型调用。

### 3. 并发与扩容

当前线程锁、turn counter、embedding 缓存、模型对象和指标都是进程内的。必须明确：

- 单 worker 单进程是当前支持模式；或
- 迁移到外部锁、外部指标和适合并发的数据库后再启用多 worker。

在没有完成迁移前，不建议直接通过增加 Uvicorn worker 数量扩容。

### 4. Docker 和脚本统一

统一以下内容：

- 对外端口：compose、deploy、restart 不应一个使用 8000，一个使用 80。
- 数据目录：SQLite、checkpoints、Chroma 的卷路径保持一致。
- 启动命令：开发 reload 和生产无 reload 分开说明。
- 模型缓存、网络源和首次下载的耗时。
- `.env` 的必填项、可选项、默认值和密钥轮换流程。

### 5. 线上保护

- HTTPS 和反向代理由部署层负责，并记录真实请求 ID。
- 限制请求体大小、登录尝试、单用户并发和长连接数量。
- `/metrics` 与管理类接口不能无保护暴露到公网。
- 日志不打印 API key、密码、完整 token、完整对话原文或不必要的 Steam 个人信息。
- 备份 SQLite、Chroma 和 checkpoint，并定期演练恢复。

## 验收标准

- 新环境按一份说明即可启动，开发和生产命令不会互相矛盾。
- 容器重建不会丢失游戏索引、用户消息或对话检查点。
- 依赖不可用时 readiness 返回失败，用户得到明确错误而不是假成功。
- 客户端断开 SSE 后，Agent 能停止或最终正确记录取消状态。
- 多 worker 未启用前，部署文档明确写出单进程限制。

## 必须补的测试

- API 请求 schema、错误 schema、SSE 事件顺序。
- 连接中断、超时、重复提交、代理断开。
- 容器重启后的数据持久性。
- readiness 对缺少 key、损坏数据库、缺少索引的响应。
- 端口、数据卷和环境变量的一致性检查。
