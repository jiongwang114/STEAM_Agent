## 一、产品目标与范围

### 核心目标

用户登录后，在一个持续的聊天工作台中获得 Steam 游戏推荐，并能够：

- 继续查看历史会话和历史消息。
- 回看每次 Agent 回答经历的关键执行步骤。
- 绑定或更换 Steam ID，获得个性化推荐。
- 在登录失效、流式中断、Agent 降级和网络失败时得到明确反馈。

### 当前不设计的页面

当前后端没有对应接口，因此暂不设计：

- Steam 游戏库独立页面。
- 游戏详情或价格管理页面。
- 用户资料编辑页面。
- 密码找回和第三方登录页面。
- 运维监控页面。

## 二、已确认的产品决策

### 1. 入口页面

- 取消全屏封面页。
- 页面打开后直接进入聊天工作台。
- 未登录用户可以看到简洁欢迎空状态，但发送消息前需要登录。
- 不通过浏览器缓存判断登录状态，启动时以服务端 Session 查询结果为准。

### 2. 主页面关系

桌面端使用“会话侧栏 + 聊天工作区”结构：

```text
┌────────────────┬────────────────────────────────────┐
│ STEAM PLAY     │ 当前会话标题       用户 / 设置      │
│ + 新建会话     ├────────────────────────────────────┤
│ 搜索会话       │                                    │
│ 最近会话       │          消息时间线                 │
│                │                                    │
│                │          执行过程（默认折叠）        │
│ 设置           ├────────────────────────────────────┤
│                │ 输入框                         发送 │
└────────────────┴────────────────────────────────────┘
```

移动端将侧栏变为抽屉，顶部保留菜单、当前会话标题和设置入口，输入框固定在底部。

### 3. 认证行为

页面启动时调用 `GET /auth/user-info`：

```text
页面启动
  -> GET /auth/user-info
      -> 200：进入已登录状态，加载会话和用户设置
      -> 401：进入未登录状态
```

- 登录和注册成功后重新调用 `GET /auth/user-info`。
- 任意受保护接口返回 `401` 时，清除前端用户状态并打开登录界面。
- Session 由 HttpOnly Cookie 保存。
- 新前端不再使用 `localStorage` 保存或恢复用户名来判断登录。

### 4. 流式聊天行为

新前端以 `POST /chat/stream` 作为默认聊天入口，只发送：

```json
{
  "thread_id": "thread_xxx",
  "message": "用户消息"
}
```

不再发送旧兼容字段 `user_id` 和 `steam_id`。

事件处理：

- `status`：显示当前工具或 Agent 处理状态。
- `token`：持续追加助手回答。
- `error`：显示可恢复错误，同时继续等待兜底文字和 `done`。
- `done`：结束流式状态，保存最终回答、执行摘要和运行状态。

流式期间发送按钮变为“停止生成”。停止时调用后端取消接口，保留已经生成的内容并标记为未完成。切换会话或刷新只断开当前订阅，Agent 会继续运行，重新打开会话时恢复运行快照。

`status: degraded` 的回答仍然展示，但需要有“回答可能未完整完成”的明确提示和重新发送入口。

### 5. 历史消息与执行过程

历史消息不能只显示用户问题和助手最终回答，还需要保留本轮 Agent 的关键执行过程。

前端显示方式：

```text
助手回答内容

查看执行过程 · 2 个步骤
  ✓ 查找相似游戏
  ✓ 查询 Steam 商店
```

执行过程默认折叠，用户主动展开后查看。

只展示用户可理解的安全摘要，不展示：

- 系统提示词。
- 原始工具参数和完整工具结果。
- 模型名称、内部 token 和 checkpoint 内容。
- `save_user_insight` 等内部持久化动作。

当前 `messages` 表保存用户消息和助手回答，执行摘要保存在独立的 `execution_summaries` 表中；`GET /messages` 在助手消息上返回安全的 `execution` 字段。

### 6. 会话标题

- 第一次用户提问时触发标题生成。
- 标题模型只使用第一条用户消息，不等待完整 Agent loop 结束。
- 标题生成应与主 Agent 执行解耦，不能阻塞聊天回答。
- 标题只自动生成一次，后续不因每轮聊天重复覆盖。
- 标题保存到 `threads_meta.title`。
- 标题生成失败时使用第一条用户消息的截断文本作为备用标题。
- 用户手动重命名后，自动标题不能覆盖用户标题。

当前实现会在首轮请求通过认证和清理检查后立即领取异步标题任务，标题生成不阻塞 Agent；手动标题会将标题来源锁定为 `manual`。

### 7. 会话删除

- 删除前显示确认弹窗。
- 删除成功后直接从列表移除。
- `200` 和 `202` 都不显示“立即重试”按钮。
- 后端继续负责自动补偿清理。
- 明确失败时只显示简短提示，不把后台清理层暴露给普通用户。

### 8. Steam 与设置

设置使用抽屉，不单独跳转页面，包含：

- 用户名和注册时间。
- Steam ID 绑定和重新绑定。
- 深色/浅色主题。
- 退出登录。
- 退出所有设备。

Steam ID 绑定是可选功能，绑定接口支持当前用户重新绑定。聊天请求不发送 Steam ID，由后端从当前 Session 查询。

主题切换立即生效，同时通过 `POST /auth/theme` 保存到服务端。

## 三、必须覆盖的页面状态

- 服务端登录状态加载中。
- 未登录。
- 已登录但没有历史会话。
- 已登录并打开会话。
- 历史消息加载中。
- 流式回答中。
- 流式回答成功。
- Agent 降级回答。
- 用户主动停止生成。
- 网络失败。
- 会话删除确认。
- Steam ID 未绑定。
- Steam ID 已绑定。
- Steam ID 绑定失败。
- 主题保存失败。
- 登录状态失效。

## 四、前端职责拆分方向

新前端必须与旧 `static/index.html` 分离，预留以下职责边界：

```text
frontend/
  src/
    app/                 应用启动、认证门控、全局状态
    components/          通用按钮、弹窗、状态提示、图标按钮
    features/auth/       登录、注册、Session 失效
    features/chat/       消息、SSE、输入框、执行过程
    features/threads/    会话列表、加载、重命名、删除
    features/settings/   Steam 绑定、主题和账户操作
    services/             API 请求、错误解析、SSE 解析
    types/                接口和状态类型
    styles/               CSS 变量、布局和可替换视觉层
```

具体框架和依赖尚未在本阶段锁定，不能把尚未确认的技术选型视为已完成事项。

## 五、最终视觉方案：Library Signal / 游戏库信号台

### 产品定位

Steam Agent 面向会反复比较、回看推荐理由并持续积累游戏语境的 Steam 玩家。页面不是一次性的问答页，而是一张可以保存会话记忆、观察推荐依据、继续下一次探索的个人工作台。

### 视觉方向

“Library Signal / 游戏库信号台”把游戏库的索引感、个人收藏的痕迹和 Agent 运行中的实时信号放在同一个界面里：

- 会话侧栏承担“个人游戏发现记录”的职责，使用密度和选中状态建立记忆感。
- 消息区使用轻量时间线，不把每条内容做成独立卡片。
- 执行摘要以“推荐依据”呈现，默认折叠，只展示安全的用户可理解步骤。
- 信号红用于主要动作和未完成状态，桥接青用于处理中和信息状态，收藏金用于完成与已连接状态。
- 不使用封面英雄区、星空背景、霓虹渐变、玻璃拟态或大面积装饰动画。

### 颜色与字体

| 语义 | 浅色主题 | 深色主题 | 用途 |
|---|---|---|---|
| 冷灰纸面 | `#F1F3F0` | `#10171A` | 页面背景 |
| 索引面 | `#FFFFFF` | `#182125` | 输入区、弹窗、抽屉 |
| 石墨墨色 | `#1B2226` | `#EDF3F1` | 主文字与侧栏基底 |
| 信号红 | `#E35D45` | `#ED715A` | 主动作、未完成、提醒 |
| 桥接青 | `#3C7D8C` | `#75B2BF` | 处理中、焦点、信息 |
| 收藏金 | `#9B741D` | `#E3BB5A` | 完成、已连接、积极确认 |

字体优先使用 `IBM Plex Sans`，回退到 `Aptos`、`Segoe UI` 和 `Noto Sans SC`。工作区标题使用 28/1.15，消息正文使用 15/1.7，侧栏与辅助文字使用 11-13px；不使用全大写标题或通用衬线展示字体。

### 布局与响应式规则

桌面端使用 272px 会话侧栏和自适应聊天区，聊天内容最大宽度约 920px。移动端在 760px 以下把侧栏变为抽屉，顶部保留菜单、当前会话标题和账户入口，输入区使用 sticky 布局并尊重安全区；320px 宽度下不产生横向滚动，长标题使用省略，长消息使用换行。

### 交互与动效原则

- 默认折叠执行过程，展开只显示安全摘要，不展示系统提示词、原始工具参数、模型名称、内部 token 或 checkpoint。
- 通过图标、文字和 `aria-live` 同时传达加载、处理中、失败、降级和主动停止状态，不依赖颜色单独传达含义。
- 动效只服务于用户动作：抽屉打开、摘要展开、主题切换和流式状态；不为页面模块批量添加无意义的渐入上移动画。
- 所有图标按钮包含 `aria-label`、`title`、清晰的 `:focus-visible` 和 disabled 状态；`prefers-reduced-motion` 时关闭非必要动画。
