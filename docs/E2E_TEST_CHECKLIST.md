## 2. 测试约定

- 每项测试记录：前置条件、操作、实际结果、预期结果、状态、证据和缺陷编号。
- 失败时保留：请求时间、`X-Request-ID`、浏览器控制台、网络响应、服务端日志和截图。
- 不在日志、截图或缺陷中记录密码、Session Cookie、Bearer Token、API Key 或完整敏感工具参数。
- 流式测试同时检查浏览器看到的内容和服务端最终持久化内容。
- 测试完成后清理测试账号、测试会话和临时数据。

## 3. 执行前检查

- [ ] 服务可启动，`GET /health` 返回 200。
- [ ] 依赖就绪，`GET /ready` 返回预期状态。
- [ ] 本地游戏数据库、向量索引和必要的索引文件已加载。
- [ ] 测试账号已准备，至少包含一个未绑定 Steam ID 的账号。
- [ ] 已准备一个有效 Steam ID、一个已被其他账号绑定的 Steam ID。
- [ ] 已准备模型成功、模型失败、工具超时、Steam API 超时等可控故障注入方式。
- [ ] 已记录本轮代码版本和环境。

## 4. 认证、权限与用户隔离

- [ ] `AUTH-01` 注册有效账号后自动建立登录状态。
- [ ] `AUTH-02` 重复用户名、非法用户名、短密码、超长输入和限流提示正确。
- [ ] `AUTH-03` 正确登录成功；错误密码返回明确错误且不泄露账号信息。
- [ ] `AUTH-04` 退出后访问受保护接口返回未登录，并回到登录状态。
- [ ] `AUTH-05` Session 过期或全部撤销后，前端能恢复到未登录页面。
- [ ] `AUTH-06` 用户 A 不能读取、修改或删除用户 B 的会话、消息和标题。
- [ ] `AUTH-07` 请求体中的 `user_id`、`steam_id` 不能冒充或覆盖服务端身份。

## 5. 输入与安全检测

- [ ] `SEC-01` 空消息、空格消息、超长消息和非法 `thread_id` 被正确拒绝。
- [ ] `SEC-02` Prompt Injection、越权请求、系统提示词探测被拦截或安全降级。
- [ ] `SEC-03` 含脚本、HTML、恶意 Markdown、链接的输入不会造成前端执行或布局破坏。
- [ ] `SEC-04` 安全检测正常通过时不会误阻断普通游戏推荐请求。
- [ ] `SEC-05` 安全检测服务异常、超时或返回异常格式时，系统采用明确安全兜底。
- [ ] `SEC-06` 模型回答不泄露系统提示词、密钥、Token、原始工具参数、完整工具结果或 checkpoint。

## 6. 会话生命周期与持久化

- [ ] `THR-01` 首次发送消息自动创建会话，并生成可见标题或兜底标题。
- [ ] `THR-02` 自动标题任务不阻塞聊天；用户手动改名后不会被自动标题覆盖。
- [ ] `THR-03` 会话列表显示正确的标题、最近活动时间和消息数量。
- [ ] `THR-04` 切换会话后加载正确消息，不串会话、不串用户。
- [ ] `THR-05` 刷新浏览器后，会话列表、历史消息和执行摘要仍可恢复。
- [ ] `THR-06` 点击其他页面、重新登录或重新打开浏览器后，正在运行/已完成会话仍能按产品约定显示。
- [ ] `THR-07` 修改标题、删除会话成功后列表和详情同步更新。
- [ ] `THR-08` 删除部分失败返回可恢复状态；清理任务可自动或手动重试。
- [ ] `THR-09` 清理未完成期间继续发送消息得到明确冲突提示，不产生半完成数据。

## 7. RAG 与本地游戏数据库

- [ ] `RAG-01` 服务启动后能确认本地几百款游戏数据库和向量索引已就绪。
- [ ] `RAG-02` 精确游戏名、别名、关键词和自然语言描述均能检索到预期游戏。
- [ ] `RAG-03` 多条件检索（类型、平台、时长、人数、偏好等）结果符合条件。
- [ ] `RAG-04` 相似游戏检索结果相关，结果数量、排序和去重符合预期。
- [ ] `RAG-05` 无匹配、低置信度、数据库为空或索引损坏时能明确降级，不编造游戏。
- [ ] `RAG-06` 检索结果正确传入 Agent，并体现在最终回答中。
- [ ] `RAG-07` 重启服务后索引仍可使用；索引未就绪时 `/ready` 和聊天行为正确。

## 8. Agent 决策与工具调用

- [ ] `AGT-01` 普通问题无需工具时不会误调用工具。
- [ ] `AGT-02` 需要 RAG、Steam 商店、用户画像或历史记忆时选择正确工具。
- [ ] `AGT-03` 工具参数符合约束，不包含越权用户或错误 Steam ID。
- [ ] `AGT-04` 工具成功、空结果、业务错误和异常结果均能生成可理解回答。
- [ ] `AGT-05` 工具连续调用顺序正确，工具结果不会错配到其他轮次。
- [ ] `AGT-06` 重复调用、无限调用和超出最大轮次时能停止并返回降级结果。
- [ ] `AGT-07` 工具超时、取消、重试和重试失败都有明确终止原因。
- [ ] `AGT-08` 同一请求不会因重复提交产生重复消息或重复副作用。

## 9. 实时流式聊天与执行过程

- [ ] `SSE-01` 连接建立后按顺序收到状态、工具过程、增量文本和 `done` 事件。
- [ ] `SSE-02` 工具开始、成功、失败状态完整；不会长期停留在“处理中”。
- [ ] `SSE-03` 增量文本无丢失、重复、乱序或乱码，最终回答与同步接口一致。
- [ ] `SSE-04` 工具调用过程展示名称、状态和耗时正确；不展示敏感内部细节。
- [ ] `SSE-05` 网络断开、浏览器刷新、切换会话和用户主动停止时，UI 状态正确。
- [ ] `SSE-06` 断开和刷新只结束订阅，活动 Agent 可恢复；显式停止后保留已生成内容。
- [ ] `SSE-07` 流中可恢复错误会显示错误和兜底文字，并最终发送或持久化正确结束状态。
- [ ] `SSE-08` 服务端异常时不会让前端无限转圈、无限重连或重复发送。
- [ ] `SSE-09` 刷新后重新加载消息时，历史执行摘要来自持久化记录；活动回答从运行快照恢复。

## 10. Steam ID 与外部 API

- [ ] `STEAM-01` 17 位数字 Steam ID 可绑定并能在用户信息中显示。
- [ ] `STEAM-02` 空值、非数字、位数错误和明显非法值被拒绝。
- [ ] `STEAM-03` 同一 Steam ID 可被多个账号绑定；其中一个账号重新绑定时，不影响其他账号的绑定。
- [ ] `STEAM-04` 重新绑定后用户画像、缓存和后续推荐使用新 ID。
- [ ] `STEAM-05` Steam API 网络失败、DNS 失败、连接拒绝、超时和 5xx 均能明确降级。
- [ ] `STEAM-06` Steam API 限流、空响应、字段缺失和异常 JSON 不会导致 500 或错误绑定成功。
- [ ] `STEAM-07` 绑定主记录与结构化画像更新保持事务一致；失败时不产生半绑定状态。
- [ ] `STEAM-08` Steam API 恢复后重试行为正确，且不会重复创建数据。

## 11. 错误、超时与恢复

- [ ] `ERR-01` 模型不可用、数据库异常、向量库异常和内部异常均返回明确失败/降级状态。
- [ ] `ERR-02` 请求超时后前端停止加载并提供可用重试路径。
- [ ] `ERR-03` 失败响应包含稳定错误码和 `request_id`，响应头与错误体一致。
- [ ] `ERR-04` 任何业务失败不会被误报为成功，也不会保存不完整的“成功”消息。
- [ ] `ERR-05` 重试具有幂等性，不生成重复消息、重复标题或重复绑定记录。
- [ ] `ERR-06` 服务重启后未完成标题、记忆和清理任务可以继续或安全终止。

## 12. 前端显示与跨设备

- [ ] `UI-01` 登录、空会话、加载、流式处理中、成功、降级、错误和重试状态清晰。
- [ ] `UI-02` 会话列表和消息加载失败时有明确提示，不显示空白页面。
- [ ] `UI-03` 执行摘要可查看，内容与历史接口一致。
- [ ] `UI-04` 用户输入和后端 Markdown/富文本经过安全处理。
- [ ] `UI-05` 桌面端和移动端无遮挡、溢出、不可点击或文本截断问题。
- [ ] `UI-06` 主题保存失败时不会假装成功，刷新后主题与服务端一致。
- [ ] `UI-07` 关键操作按钮在请求中有禁用/防重复提交状态。

## 13. 并发与一致性

- [ ] `CON-01` 同一用户多个标签页同时聊天，消息和会话列表最终一致。
- [ ] `CON-02` 同一会话快速连续发送时，轮次、顺序和执行摘要不混乱。
- [ ] `CON-03` 同一用户同时删除和发送消息时，清理状态和冲突提示正确。
- [ ] `CON-04` 多用户同时绑定同一 Steam ID 时只有一个成功。
- [ ] `CON-05` 服务重启或网络短暂中断后，数据库没有重复或孤立记录。

## 14. 部署与运维

- [ ] `OPS-01` 缺少关键配置时启动或 `/ready` 明确失败。
- [ ] `OPS-02` `/health` 只反映进程存活，`/ready` 正确反映依赖和索引状态。
- [ ] `OPS-03` 指标接口在无 Token、错误 Token、正确 Token 下行为符合预期。
- [ ] `OPS-04` 可通过 `request_id` 将一次前端请求、后端日志和错误关联起来。
- [ ] `OPS-05` 日志不包含密码、Cookie、Token、API Key、系统提示词或敏感工具数据。
- [ ] `OPS-06` 服务重启后已有会话、历史消息和后台补偿任务可恢复。
